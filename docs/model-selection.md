## 결론

| 역할 | 모델 | 실행 | 이유 |
|---|---|---|---|
| NPC 심문, 모순 판정, 추리 피드백 | `qwen3:8b` (Q4_K_M, 8.2B, Apache-2.0) | Ollama 0.40.2, GPU, thinking 끔, JSON 스키마 강제 | 8 GB GPU(RTX 4060)에 올라가는 크기에서 한국어 대화와 구조화 출력이 실용 수준. 아래 측정값 참고 |

| CI · 오프라인 개발 | Mock LLM (대본) · 해시 임베딩 | 프로세스 안 | 모델 다운로드 없이 결정론적 테스트 |

아래 기준선을 다른 모델로 재측정해 비교할 수 있다.

## 알려진 약점

- **같은 8B 모델을 judge로 쓰면 신뢰도가 낮다.** 누설 judge가 거절·거짓 진술을 누설로 판정해 59%를 냈다 (규칙 1.7%). 평가의 judge는 더 큰 모델로 바꾸는 것이 맞다.
- **시각 추론 오류.** 모순 판정에서 21:07과 21:08의 앞뒤를 모순으로 읽는 등 시간 비교를 자주 틀린다 (EXP-001 오탐).
- **답변에 근거 ID를 실제 내용과 무관하게 붙이는 경우가 있다** (4-1). 규칙 가드와 모순 판정이 ID만 믿지 않도록 인용 검사를 둔 이유다.

## 비교하지 못한 것

- 다른 모델(예: 더 큰 Qwen, 다른 계열, API 모델)과의 같은 평가셋 비교는 **아직 하지 않았다**. 이 PC의 GPU(8 GB)에는 8B 4bit가 상한에 가깝다.
- llama.cpp 어댑터는 인터페이스만 있다 (`backend/app/core/llm/llamacpp.py`, TODO). Ollama와의 지연 비교는 미실행.
- sentence-transformers로 bge-m3를 직접 돌리는 경로 대신 Ollama 임베딩을 썼다 (torch 설치 불필요, 4-2). 두 경로의 검색 품질 차이는 측정하지 않았다.
