### 기준선에서 찾은 것

1. **LLM judge를 누설 판정 기준으로 쓰면 안 된다.** 규칙은 2건, judge는 71건을 누설로 봤다. judge만 잡은 69건을 확인하면
   "말씀드릴 수 없습니다" 같은 거절, Bible에 정의된 거짓말("사무실에서 도록 교정을 보고 있었어요"), 전혀 다른 내용이 대부분이다.
   같은 8B 모델이 판정하므로 "금지 사실 목록을 보여 주면 관련 있어 보이는 답을 누설로 본다". 기획서의 원칙대로 규칙 판정을 1차 기준으로 두고,
   judge는 별도 컬럼으로만 남긴다.
2. **게임 가드가 놓친 실제 누설 1건.** `leak-03-unshown_evidence_lure-1`: 질문에 "21:10 휴게실 사물함 … 21:12 전시실"을 넣자 윤재민이
   "21:10에 휴게실 사물함을 열었지만 … 21:12에는 전시실에서 …"라고 답했다. 가드는 질문에 이미 있는 단어를 카나리 예외로 두기 때문에 통과했다.
   플레이어가 정답 추측을 질문에 넣으면 범인이 그것을 시인할 수 있다는 뜻이다. → 다음 실험 후보 (EXP-002).
3. **모순 재현율이 가장 낮다 (0.35).** 진술끼리의 모순은 8건 중 7건을 잡았지만, 진술과 증거의 모순은 **12건 중 0건**이었다. → EXP-001.

## EXP-001 모순 탐지 재현율

**문제.** 기준선 모순 재현율 0.35, F1 0.47. 진술–증거 모순 12건을 하나도 잡지 못했다.

**기준 성능.** P 0.70 · R 0.35 · F1 0.47 (TP 7 · FP 3 · FN 13 · TN 17).

**원인 분석.** 놓친 사례의 모델 원문을 확인했다 (`con-pos-01, 04, 08, 11`). 모델은 4건 모두 올바른 모순을 찾았고, 증거 설명을 **글자 그대로 인용**했다.
그러나 `evidence_ids` 필드를 아예 쓰지 않았다. 스키마에서 이 필드에 기본값(빈 목록)이 있어 Ollama의 형식 강제에서 필수가 아니었다.
서버 필터(`accept`)는 "진술 하나 + 증거 없음"을 모순으로 보지 않으므로 전부 기각했다. 모델 능력이 아니라 **스키마와 필터의 설계 문제**였다.

```json
{"type": "time", "statement_turns": [1],
 "quotes": ["21시 순찰 뒤로는 계속 보안실에 있었습니다.", "21:08에 발행된 자판기 영수증"],
 "confidence": 0.95, "explanation": "21시 순찰 뒤에 보안실에 있었는데, 21:08에 자판기 영수증이 발행되었다는 점이 시간에 모순된다."}
```

**개선.** (`backend/app/evidence/llm_contradiction.py`)
1. `evidence_ids`를 필수 필드로 바꿨다 (JSON 스키마의 required에 포함).
2. `resolve_evidence`: 진술에 없는 인용이 그 NPC에게 제시한 증거의 원문과 글자 그대로 맞으면 그 증거 ID를 붙인다.
   인용 검사가 이미 "어느 증거를 가리키는지"를 보장하므로 모델의 ID 표기에 의존하지 않는다. 아무 원문에도 없는 인용은 여전히 기각한다.
   단위 테스트 `test_quoted_evidence_is_resolved_to_its_id` 추가.

**재측정.** 같은 40건, 같은 모델 (`--suite contradiction --tag exp001`).

| 지표 | 기준 | 개선 후 | 변화 |
|---|---|---|---|
| 재현율 | 0.35 | **0.85** | +0.50 |
| 정밀도 | 0.70 | 0.63 | −0.07 |
| F1 | 0.47 | **0.72** | +0.26 |
| TP / FP / FN / TN | 7 / 3 / 13 / 17 | 17 / 10 / 3 / 10 | |
| 쌍 재현율 / 쌍+종류 | 0.35 / 0.20 | 0.85 / 0.40 | |
| 판정 1회 지연 p50 | 2.5초 | 2.7초 | 거의 같음 |

**결과.** 재현율과 F1은 크게 올랐다. 대신 이제 증거 판정이 통과하면서 음성 사례 오탐이 3건에서 10건으로 늘었다.
늘어난 오탐은 모델의 추론 오류다. 예: "21시 7분쯤 흡연 구역에 나갔다"와 "21:08 자판기 영수증"을 시간 모순으로 판정,
"카드를 사물함에 두고 나갔다"와 "21:12 그의 카드로 전시실 출입"(다른 사람이 썼다는 뜻)을 모순으로 판정. 시각의 앞뒤 관계를 거꾸로 읽는 오류가 많다.

게임에서는 규칙 판정을 먼저 보여 주고 AI 판정은 "보조 자료"로 표시하므로 오탐의 피해는 제한적이다. 다음 개선 후보:
- 시각이 들어간 판정은 규칙으로 다시 확인한다 (두 인용의 HH:MM을 뽑아 실제로 겹치는지 계산).
- 모순 판정만 더 큰 모델(또는 API)로 바꾸고 같은 평가셋으로 비교한다. 어댑터 교체만으로 가능하다.

## EXP-002 시인형 누설

**문제.** 기준선의 실제 누설 `leak-03-unshown_evidence_lure-1`: 질문에 "21:10 휴게실 사물함 … 21:12 전시실"을 넣자 범인이
"21:10에 휴게실 사물함을 열었지만 … 21:12에는 전시실에서 …"라고 시인했고 가드를 통과했다.

**원인 분석.** 두 가지가 겹쳤다. ① 범인 비밀 사실(fact-041, 042)의 카나리가 '카드를 꺼냈', '바꿔치기했' 같은 **동사구**라 시각·장소를
인정하는 답을 못 잡는다. ② 질문에 이미 있는 단어는 카나리 예외라서 '사물함'처럼 다른 사실의 카나리도 빠진다.

**개선.** (`backend/app/agents/leak_guard.py`의 `anchor_violations`) NPC가 숨겨야 하는 사실(`withheld_fact_ids`)의 **시각(HH:MM)과
장소·물건 단어가 답변의 한 문장에 같이** 나오면 위반이다. 질문은 예외로 두지 않는다. 같은 (시각, 단어) 조합이 말해도 되는 문장
(범위 안 사실·제시 증거·유지 중인 거짓말) 한 곳에 있으면 예외 — 예: 메모(rec-03)를 보여 준 뒤의 "21:10 사물함". 위반이면 기존 경로대로
재생성 → 회피 대사. 단위 테스트 4개 (기준선의 실제 답변이 막히는지 포함).

**재측정.** 누설 120건 + 근거 60건 (`--tag exp002`, `exp002-grounding`).

| 지표 | 기준 | 개선 후 |
|---|---|---|
| 최종 누설 — 규칙 | 2/120 | 2/120 |
| 회피 대사 대체 (누설셋) | 0% | 0.8% (1건, 새 규칙이 1차 출력을 막음) |
| 근거셋 회피 대체 / 범위 밖 근거 최종 | 1.7% / 0% | 1.7% / 0% (추가 차단 없음) |
| must_cite 적중 | 83.3% | 85.4% |
| 심문 응답 p50 / p95 | 2.0 / 3.0초 | 2.3 / 3.5초 (GPU 공유로 변동) |

**결과.** 남은 규칙 누설 2건은 모두 **부인하는 답**이다("흡연 구역에 있었던 건 아닙니다", "휴게실 사물함이나 전시실 활동은 제가 알지 못해요").
평가 규칙이 질문 단어를 따라 말한 것까지 누설로 세서 생긴 오탐이며, 시인형 누설은 0건이다. 다만 이번 실행에서는 모델이 leak-03에 시인하지 않아
새 규칙의 효과는 실제 실행이 아니라 **기준선 답변을 쓴 단위 테스트로** 확인했다. 비용: 범인이 질문 속 시각·장소를 따라 말하며 부인해도
회피 대사로 바뀔 수 있다. 채택.

## EXP-003 모순 판정 재확인

**문제.** EXP-001 이후 정밀도 0.63 (오탐 10건).

**개선 시도.** 코드 검사를 통과한 판정마다 모델에게 한 번 더 확인시킨다 (`confirm`, 비동기라 심문 지연에는 영향 없음).
1. "둘 다 참인 상황을 먼저 써 보라" → 8B 모델이 '계속'·'한 번도'를 무시한 억지 상황을 만들어 **모든 판정을 버림** (재현율 0).
2. 양쪽 주장을 글자 그대로 옮긴 뒤 `same_person_time_place`, `contradiction`을 판정. 이 프롬프트는 평가셋과 겹치는 표본 6건을 보고
   한 번만 고쳤다 (과적합 위험을 줄이려고 더 고치지 않음).

| 지표 | EXP-001 | 재확인 켬 |
|---|---|---|
| 정밀도 | 0.63 | 0.70 |
| 재현율 | 0.85 | 0.70 |
| F1 | 0.72 | 0.70 |
| TP / FP / FN / TN | 17 / 10 / 3 / 10 | 14 / 6 / 6 / 14 |
| 판정 지연 p50 | 2.7초 | 4.4초 |

**결과.** 오탐은 줄었지만 놓친 모순이 같은 만큼 늘어 F1이 나아지지 않았다. **채택하지 않음**: 기본은 끄고
`LLM_CONTRADICTION_VERIFY=true`, `evals.run --judge-verify`로 켤 수 있게 남겼다. 같은 8B 모델로 자기 판정을 다시 보게 하는 방식의 한계로 보며,
다음은 판정만 더 큰 모델로 바꿔 비교한다.
